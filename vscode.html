VSCode Integration

If you develop firmware with MPLAB X and the MPLAB VSCode extension, you can add a task to .vscode/tasks.json in your project that launches pyX2Cscope automatically after a build or flash, pointing directly at the generated ELF file.

Creating the task automatically

For a project created with the MPLAB extension for VS Code (it contains .vscode/<project>.mplab.json), pyX2Cscope writes the task for you:

pyX2Cscope.exe --vscode-task path\to\my_project      # standalone executable
pyx2cscope --vscode-task path/to/my_project          # pip install

Without a folder, the current folder is used. The task:

  • takes the ELF file of each build configuration from imagePath in .mplab.json (e.g. ./out/my_project/default.elf). Several configurations give one task each, Run pyX2Cscope (<configuration>);

  • starts the same program that created it (pyX2Cscope.exe, or Python with -m pyx2cscope), with -p AUTO by default;

  • uses ${workspaceFolder:my_project} paths. If pyX2Cscope is inside or next to the project folder (e.g. ../pyX2Cscope/pyX2Cscope.exe) the paths stay relative, so both folders can be copied together; otherwise they are absolute.

The options -p, -w, -wp and --host given together with --vscode-task are used in the task:

pyX2Cscope.exe --vscode-task path\to\my_project -w        # Web GUI
pyX2Cscope.exe --vscode-task path\to\my_project -p COM3   # fixed serial port

Other tasks in tasks.json are kept, and a task with the same label is replaced, so the command can be run again after moving pyX2Cscope. VS Code allows comments in tasks.json; they cannot be kept, so the original file is saved as tasks.json.bak first.

tasks.json example

To write the task by hand, create or edit .vscode/tasks.json in your firmware project:

Single-folder workspace — use ${workspaceFolder} when the workspace contains only one project:

{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "Run pyX2Cscope",
            "type": "process",
            "command": "${workspaceFolder}/../pyX2Cscope/pyX2Cscope.exe",
            "args": [
                "-p", "AUTO",
                "-e", "${workspaceFolder}/out/default.elf"
            ],
            "options": {
                "cwd": "${workspaceFolder}/../pyX2Cscope"
            },
            "presentation": {
                "reveal": "always",
                "panel": "new"
            },
            "problemMatcher": []
        }
    ]
}

Multi-folder workspace — when the .code-workspace file contains several folders (e.g. MY_Project1, MY_Project2), use ${workspaceFolder:MY_Project1} to refer to a specific folder by name:

{
    "version": "2.0.0",
    "tasks": [
        {
            "label": "Run pyX2Cscope (MY_Project1)",
            "type": "process",
            "command": "${workspaceFolder:MY_Project1}/../pyX2Cscope/pyX2Cscope.exe",
            "args": [
                "-p", "AUTO",
                "-e", "${workspaceFolder:MY_Project1}/out/MY_Project1/default.elf"
            ],
            "options": {
                "cwd": "${workspaceFolder:MY_Project1}/../pyX2Cscope"
            },
            "presentation": {
                "reveal": "always",
                "panel": "new"
            },
            "problemMatcher": []
        }
    ]
}

Adapt the command path to where pyX2Cscope.exe is located on your machine, and update the -e path to match your project’s output ELF. For multi-folder workspaces, replace MY_Project1 with the folder name as it appears in your .code-workspace file.

To launch the Web GUI instead of the Qt GUI, add "-w" to the args list:

"args": ["-p", "AUTO", "-e", "${workspaceFolder:MY_Project1}/out/MY_Project1/default.elf", "-w"]

Running the task

Once configured, run it from Terminal → Run Task → Run pyX2Cscope (or bind it to a keyboard shortcut). pyX2Cscope will open with the correct ELF loaded and attempt to connect to the device on the first available port — no manual input needed.

Tip

Combine this with a build or flash task using dependsOn so that pyX2Cscope launches automatically after every successful firmware flash:

{
    "label": "Flash and Run pyX2Cscope",
    "dependsOn": ["Flash Device", "Run pyX2Cscope"],
    "dependsOrder": "sequence",
    "problemMatcher": []
}
